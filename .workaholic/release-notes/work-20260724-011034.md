# Prove the declared Slack twin and retire the compiled /cf queue pull

## Summary

"Connect a new service by writing a declaration, not by compiling a Rust driver" stays a slogan until a compiled service driver actually falls. This release is the first attempt at that fall. It declares the whole Slack read surface and proves it row-equivalent to the compiled driver on hermetic fixtures, ships the three blueprint capabilities the conversion needed, and **does retire one compiled surface** — the `/cf` queue-pull, twinned, proven equivalent on a wire fixture, then deleted. `driver-slack` itself stays: a declared write cannot turn `#general` into a channel id, and the reason is structural.

## Key Changes

- `slack_driver.qfs` declares the Slack read surface plus post and five typed CALL maps, row-equivalent to `driver-slack` on shared fixtures — the DM read over POST included
- **G2** declared PUSHDOWN shipped end to end, with EXACT/PREFILTER residual honesty: Slack's bounds are inclusive, so `>=`/`<=` mean the predicate exactly while a strict `>`/`<` is pushed as a looser prefilter and the conjunct is **kept** so the engine re-excludes the boundary row locally
- **G5** typed CALL signatures plus declared-CALL dispatch — and a lexer fix for a bug that had left `slack.update` and `slack.delete` advertised but **uncallable since v0.0.89**
- **G4** per-row fan-out `|> FOLLOW <field> INTO /http/<drv>/<template>`, confinement re-checked per row, bounded at 50 and **refusing rather than truncating**
- The compiled `/cf` queue-pull is gone, and its capability set narrowed from `{INSERT, SELECT}` to `{INSERT}` in the same commit — the advertisement fell with the capability

## Changes

### Added
- `|> FOLLOW <field> INTO /http/<drv>/<template>` per-row fan-out; declared `PUSHDOWN` on `CREATE DRIVER`/`CREATE VIEW` with a `sys_drivers.pushdown` System DB migration; typed `CREATE MAP CALL <drv>.<action> ( … )` signatures surfaced on `DESCRIBE`

### Removed
- The compiled `/cf` queue **read**: the trait method, HTTP implementation, mock arm, `QueueMsg` DTO, `CfDriver::queue_tail` and the queue read facet. Reading a queue now returns a structured refusal naming the declared view that replaced it

### Changed
- A `CALL` action name may be a keyword-shaped word, so `slack.update` and `slack.delete` are callable for the first time since v0.0.89
- Two guide pages and five blueprint claims corrected — they described the pre-release world, and one told readers to use the `/cf` queue read this release deletes

## Upgrade Notes

**Breaking for `/cf` queue readers.** `select … from /cf/queue/<name>` no longer returns rows; it refuses and names the declared replacement, `/cloudflare/accounts/<account>/queues/<queue>/messages/pull`. Queue **push** on the compiled driver is unchanged.

The plugin is bumped **minor** (0.17.0 → 0.18.0) because the retirement changed the `qfs-cloudflare` taught surface; installed skill caches need the bump.

## Known Gaps

- `driver-slack` is **not** retired. A declared write cannot resolve a channel name: Slack offers no name-addressed channel endpoint, so the compiled driver GETs `conversations.list` and scans the array locally — a reverse lookup against a collection, not a substitution into an address, which is the opposite of what G4 does. The mission was closed `carried` into successor `a-declared-write-resolves-a-name-the-way-a-query-does`, where the recommended fix needs **zero new grammar**: `let` already expresses the lookup, and only fails inside a declaration because a map body parses as `inner_statement`, which excludes `let_binding`.
- The `/cf` queue-pull equivalence proof is now a **recorded** oracle, not a live one — the compiled pull was deleted in the same commit, so the regression bar is the recorded rows.
- §13.2's calibration table was mis-measured on every pre-existing row (it counted prose semicolons in comment headers). Re-measured here, and the first real conversion lands **at** the ~40 statement-line bar rather than under it, so the remaining github/drive/mail projections are optimistic by roughly a third.
