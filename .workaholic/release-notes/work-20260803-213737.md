# A declared write resolves a name, and the compiled Slack driver is retired

## Summary

A declared integration can now turn a human-readable name into the id an API demands, using the same
query syntax you would type at the shell. With that in place the compiled Slack driver is deleted:
`/slack` is served entirely by a declaration written in qfs's own language.

## Key Changes

- A declared map body can bind a reverse lookup with `LET`, resolved before the write fires and
  refused — never guessed — when a name matches nothing or several things.
- The five Slack procedures (react, pin, unpin, update, delete) accept a channel given either as a
  name or as an already-resolved id.
- `EXPAND` now splices a nested record by field name instead of by position, so a collection whose
  elements carry different optional keys no longer shifts columns silently.
- A map body can read its own path's parameters, so a write addressed at a path stops asking the
  caller to repeat that address in the payload.

## Changes

### Added

- `LET` reverse lookups in a declared map body (blueprint G9), and `path.<name>` references to a
  map's own path parameters.

### Changed

- `EXPAND` assigns each element's fields by name; a key an element omits reads as NULL instead of
  pulling the next column's value into its place.

### Removed

- The compiled `driver-slack` crate. `/slack` is served by the shipped `slack_driver.qfs`
  declaration.

## Breaking change

This is a hard break with no compatibility shim. `/slack` requires the `slack_driver.qfs` declaration
to be installed. The inbound Slack event/webhook signature verification went with the crate; it was
unreferenced and is not replaced.
