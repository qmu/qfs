# One Workers target, two environments, neither of them reachable without an explicit --env etc

## Summary

The documentation site now publishes itself. A merge to `main` reaches
staging-qfs.qmu.co.jp and a `v*` tag reaches qfs.qmu.co.jp, with no deploy command run by
a person in either path. Both hostnames report the commit they carry.

## Key Changes

- One Workers target, two environments, neither of them reachable without an explicit `--env`.
- Staging publishes from CI's existing `docs-build` job — one build, not a second one.
- Production waits on the Release job, so a failed binary release advertises no version.

## Changes

### Added
- A Cloudflare Workers static-assets deploy target for the VitePress build, with separate
  `staging` and `production` environments and the three `docs:deploy:*` commands.

### Changed
- CI's `docs-build` job publishes `main` to staging-qfs.qmu.co.jp, stamped non-indexable.
- The release workflow publishes the tagged documentation to qfs.qmu.co.jp after the Release job.
- The tag docs publish is gated on `gen-docs --check`, closing the gap where no CI job
  re-checks a tagged tree.
- The docs site deployment is recorded alongside the GitHub Release record, correcting the
  three places that still asserted the repository had one deployment target.
