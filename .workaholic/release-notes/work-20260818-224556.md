# Step 4 verified against the live hostnames, and the staging robots guard is one mechanism etc

## Summary

The docs deploy's step-4 check was run as the ticket specifies, against both live hostnames,
instead of the workflow-run substitute three containers fell back to. Both hostnames answer and
carry the right commit. Doing it against the deployed artifact confirmed that staging's
`robots.txt` guard does not bind and the `X-Robots-Tag` header is carrying staging alone.

## Key Changes

- Step 4 met directly: staging reports `origin/main`'s head, production the newest tag, both `200`.
  Nothing detached when the `routes` were removed.
- The staging `robots.txt` `Disallow: /` does not bind — Cloudflare prepends a managed
  `User-agent: *` / `Allow: /` group, and RFC 9309 merges same-agent groups taking the least
  restrictive rule. `X-Robots-Tag: noindex, nofollow` is the guard, and it is present.
- The CI token still holds zone-wide `Workers Routes: Edit`; narrowing it stays three console acts
  for the account holder.
