# Slack files read and write, private channels are discoverable, and a credential failure names itself

## Summary

Slack was the one connected service qfs could read files from and not write files to, and the one
whose channel listing could see only half its namespace. Both are closed. The error class that hid
them — a credential that could not be resolved, reported as an invalid path — now names which of
locked, absent or revoked it was, and exits on the auth code that already existed for it.

The upload was proved end to end against a live workspace rather than a fixture: a file uploaded
into a private channel and read back byte-identical.

## Key Changes

- `upsert into /slack/<ws>/<channel>/files/<name>` uploads a file through Slack's three-call
  external flow, behind one scoped transport primitive that admits only the `files.slack.com` URL
  Slack delivered and refuses every redirect on both legs.
- A `private-channels` view — a sibling, never a widening of `channels`, so a token without
  `groups:read` keeps its working public listing.
- A credential that cannot be resolved reports its store code and the action that clears it,
  against the path the caller addressed, as `kind: auth` (exit 6) instead of `kind: usage` (exit 2).
- A declared lookup can bind on `path.<param>`, not only `row.<field>`.

## Changes

### Added
- `qfs.file-upload`, the scoped Slack upload primitive (reserve → send → complete), with its own
  refusal vocabulary and seven unit cases over the mock transport.
- `CREATE VIEW /slack/{ws}/private-channels` and `CREATE MAP UPSERT
  /slack/{ws}/{channel}/files/{filename}` in the shipped declaration.
- `CfsError::Auth { path, code, hint }`, the first arm to reach `ErrorKind::Auth`.

### Changed
- `read_http_error` preserves the credential resolver's own code instead of the label `http_auth`.
- The locked-store refusal on a compiled cloud mount moves from the usage class to the auth class.
- The Slack cookbook documents the upload, the two-view discovery, and the id-only channel
  reference; the generated `qfs-slack` skill follows.
- `.workaholic/` corrects, in place, the recorded finding that `#dev-qfs` does not exist — it is a
  private channel, reachable from two of the five connected mounts.
