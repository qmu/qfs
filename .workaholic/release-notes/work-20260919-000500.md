# qfs declare: install a shipped driver declaration from the binary that carries it

## Summary

A declared driver is config, and upgrading the binary never updates it — so a current qfs could run
a declaration older than itself, which is exactly how a Slack mount ended up able to list
attachments and unable to read one. `/sys/declarations` could already name that drift; there was no
command to act on it. There is now.

## Key Changes

- `qfs declare` lists the four declarations this binary ships, with the statement count each install
  writes.
- `qfs declare <driver>` lists those statements and writes nothing; `--commit` installs or refreshes
  the declaration. No download and no copy-paste: the source is the artifact already on the machine.
- Re-installing is safe (a declaration's identity is `(kind, name, verb)`, and the superseded row is
  replaced in the same transaction), and the first failing statement stops the run with its own exit
  code.

## Changes

### Added
- `qfs declare [<driver>] [--commit]`, with the shipped set injected through a `DeclarationProvider`
  exactly as the embedded skill is, so `qfs-cmd` stays off `qfs-skill`.
- Five unit cases over the new command: the listing, the refusal for an unshipped driver, the
  preview default, driver-name derivation, and the manifest headline.

### Changed
- `docs/cookbook/faq.md`'s declaration-currency answer ends in an action instead of a manual
  procedure; the Slack cookbook prescribes `qfs declare slack --commit` where it prescribed a
  by-hand re-install. Skills regenerated.
