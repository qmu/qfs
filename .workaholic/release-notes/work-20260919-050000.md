# A declared write addressed at its target sends the request its body declares

## Summary

Deleting a Slack file reported `committed: true` and deleted nothing — no wire request was made at
all. Two stacked defects in the declared-map write path, both fixed here, and both applying to every
declared driver rather than to Slack.

## Key Changes

- A write ADDRESSED at its target (`remove /slack/<ws>/files/<id>` — the file is named in the path,
  so there is no input row) now evaluates its body once with `path.<param>` bound. It used to build
  one body per row, and with no rows it built none, sent none, and reported success.
- A declared map's wire leg now uses the verb its own body declares, for every map kind. Only a
  `CALL` map's verb was honoured before, so `CREATE MAP REMOVE … AS INSERT INTO
  /http/slack/files.delete` went out as `DELETE`, which Slack answers `invalid_arguments`.
- A rowless write whose body reads `row.<field>` is refused before the wire instead of sending nulls.

## Changes

### Changed
- `qfs-exec`'s `eval_map_body` evaluates an address-only write once, and refuses one that needs a row.
- `apply_facets` takes the wire effect kind from the map body for universal-verb maps too.
