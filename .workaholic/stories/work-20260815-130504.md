## 1. Overview

The scheduled `[Propose]` and `[Implement]` cloud routines fired on time but stopped immediately because a fresh Claude Code web container never installed the workaholic plugin. This branch installed the workaholify web bootstrap into the repository — the canonical SessionStart hook, its registration in `.claude/settings.json`, and a git-identity map — so a cloud session comes up with the plugin present and the developer's identity set.

**Highlights:**

1. Added `.claude/hooks/session-start.sh` as a byte-for-byte copy of the workaholic v1.0.177 canonical bootstrap, so the gateway's `matches_canonical` check holds.
2. Created `.claude/settings.json` with the `SessionStart` hook (matcher `startup`, timeout 120), `enabledPlugins: workaholic@workaholic`, and the `qmu/workaholic` marketplace entry.
3. Added `.claude/git-identities` mapping `tamurayoshiya=a@qmu.jp`, clearing all four `check-bootstrap.sh` findings and bumping the patch to 0.0.98.

## 2. Motivation

Both hourly account routines created on 2026-08-14 were configured correctly and fired on schedule, yet did nothing: the 19:44 JST tick posted `⚪ Paused - unbound_in_claude_session` to `dev-qfs` because `Skill(implement)` resolved to an unknown skill in a fresh web container, and the routine prompt's fallback exited 127 since this checkout's `plugins/` carries only the qfs plugin (issue #44). A routine that fires and silently accomplishes nothing reads as healthy from the routines list — exactly the failure mode overnight AI runs must not have. The repository therefore needed the thin web bootstrap that installs the plugin at session start — verbatim from the plugin's canonical copy, since the gateway compares it byte-for-byte and policy-as-plugin keeps the standards themselves out of this repository.

## 5. Concerns

### Bootstrap installs the plugin but does not guarantee it is bound

- **Severity:** moderate
- **Description:** The hook makes the plugin *installed* in a web session, not necessarily *bound* — a session binds whatever the registry named before SessionStart ran, and the issue #44 fallback (`plugins/workaholic/.../plugin-src.sh`, absent from this checkout) still exits 127 (see [f77898a](https://github.com/qmu/qfs/commit/f77898a) in `.claude/hooks/session-start.sh`).
- **How to Fix:** Treat the first post-merge tick as the proof; if it still pauses, pursue the harness-side rebind and the issue #44 fallback fix, never a local patch of the canonical hook.

## 6. Successful Development Patterns

- Install a canonical bootstrap verbatim and let the checker prove it: `check-bootstrap.sh` names each problem separately and compares the hook byte-for-byte, so copying the file unmodified turns a four-part acceptance criterion into one machine-checked run.
