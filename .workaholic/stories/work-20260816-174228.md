## 1. Overview

The FAQ described exit `2` as "parse or CLI usage error", which is not what an operator most often
hits: the two structured stage refusals, `unknown_column` and `not_expandable`, are
`ErrorKind::Usage` and exit 2 while being neither. The row now names the class honestly and the
table above it carries a row for each refusal, quoting the binary's own message.

**Highlights:**

1. Exit 2 reads "a malformed question — a parse error, a CLI usage error, or a stage naming something the relation does not have".
2. Two new common-errors rows, each quoting a real run and pointing at `qfs describe <path>`.
3. Measurement found a third rendering of the same refusals, minted as its own ticket.

## 2. Motivation

`docs/cookbook/faq.md` is the operator's troubleshooting surface and the source of the `qfs-faq`
Agent Skill an agent consults when a command fails. A refusal is only useful if the page that
explains it sends the reader to the right place, and this one sent them to check their flags: the
common-errors table above the exit codes carried no row for either refusal, so nothing anywhere
said what to actually do. The refusals are this mission's own product, which makes
under-describing them this mission's own debt.

## 5. Concerns

### A post-decode refusal reports a different stable code than the same mistake before a decode

- **Severity:** moderate
- **Description:** After a `decode`, `unknown_column` and `not_expandable` are re-wrapped as `codec_then_query` carrying the Rust `Debug` form of the error enum (`post-decode evaluation failed: UnknownColumn { stage: "where", … }`), so one mistake has two stable codes and this branch's new FAQ rows are true only on the pre-decode path (see [b73fc15](https://github.com/qmu/qfs/commit/b73fc15) in `packages/qfs/crates/core/src/eval.rs`)
- **How to Fix:** Re-raise the structured refusal through the codec seam with its own code and prose message, keeping `codec_then_query` for post-decode failures that are not one of them. Ticketed at `20260816175149-post-decode-refusals-leak-the-rust-debug-form.md`.

## 6. Successful Development Patterns

- Quoting an error from a real run rather than from the ticket's prose caught a wrong claim before it shipped: the ticket grouped "absent, scalar, or `Json`" under `not_expandable`, but an absent column raises `unknown_column` — the refusals split on "is it there" before "can it explode".
