## 1. Overview

Eight tests in `declared_driver.rs` each carried their own copy of the config install path's
statement splitter. All eight now go through the one `shipped_statements` helper the Chatwork tests
already used, plus a thin `shipped_statements_of_kind` built on it for the Slack twin harness's
per-kind extractors.

**Highlights:**

1. Three character-for-character duplicates of a 24-line splitter deleted; net −92 lines.
2. The four Slack per-kind extractors and the G2 pushdown lookup express themselves over one statement list.
3. No assertion changed — extraction only, which is the ticket's own definition of done.

## 2. Motivation

The splitter has to stay identical to the install path, or a test proves something about a statement
list the installer would never produce. Independent copies are independent places for that to drift,
and this bit once already: when the Slack CALL maps moved their channel binding to a shared
`CREATE LOOKUP`, the twin harness had no extractor for the new statement kind and four equivalence
tests silently drove maps whose lookup was simply absent. They failed loudly only because the
assertions were strong.

## 3. Changes

### 3-1. Fold the shipped-asset splitter onto one helper ([6076d4b](https://github.com/qmu/qfs/commit/6076d4b))

`shipped_slack_script_installs_statement_for_statement`, its cloudflare twin and the github_account
credential-free test each dropped their inline splitter for `shipped_statements(script)`. The Slack
twin harness's `shipped_slack_maps` / `_views` / `_lookups` / `_types` and the G2 pushdown test's
driver-statement lookup now read through `shipped_statements_of_kind`, so a new statement kind is
taught in exactly one place.

## 4. Outcome

Eight call sites, one splitter. `cargo test --workspace` 2719 passed / 0 failed, clippy
`-D warnings` clean, fmt clean, `gen-docs --check` / `gen-skills --check` / `check-migrations` in
sync. A grep for an inline split on `;` in `declared_driver.rs` now returns nothing.

## 5. Concerns

### The inline copies had already drifted from the helper on comment handling

- **Severity:** low
- **Description:** The helper strips `#` whole-line comments and the five Slack extractors did not, so the tests and the installer would have split differently for any asset using one (see [6076d4b](https://github.com/qmu/qfs/commit/6076d4b) in `packages/qfs/crates/qfs/src/declared_driver.rs`). No shipped `.qfs` asset uses `#` today, so the fold was behaviour-preserving — the divergence had simply not been reached yet.
- **How to Fix:** Fixed by this branch. Worth noting that the drift arrived in comment handling rather than in statement kinds, which is the direction the ticket anticipated.

## 6. Successful Development Patterns

- Grepping for the mechanism (`split(';')`) rather than for the ticket's four cited line numbers found eight call sites where the ticket named "at least four" — the line numbers had moved and the count was low.
