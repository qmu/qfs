## 1. Overview

A codec seam reports `Schema::empty()` by design, and four downstream folds were made lenient for
it. `check_of_assertion` was the fifth and was missed, so `… |> decode <fmt> |> of <type>` diffed
the asserted columns against an empty schema and reported every one of them missing. It is now
late-bound like its siblings.

**Highlights:**

1. `decode |> of` plans clean; the assertion rides to the next materialising boundary.
2. Leniency applies *after* type resolution, so an unknown name is still `of_type_unresolved`.
3. The new test was confirmed to fail with the arm reverted — a regression test, not a tautology.

## 2. Motivation

The error was not merely wrong, it was wrong in the specific way the codec-schema work existed to
remove: a plan-time refusal listing columns as missing from a schema that is empty by construction,
fired before the decode that would have produced exactly those columns. The ticket named two
defensible answers and forbade assuming either. Lenient wins on evidence already in the tree — the
ticket's Policies section requires the five folds to state one rule about an undescribable relation,
and four already say lenient; the explicit refusal is the option the ticket calls a deliberate
ruling, which an unattended run does not hold.

## 3. Changes

### 3-1. Let `of` ride late-bound past a codec seam ([a77f597](https://github.com/qmu/qfs/commit/a77f597))

`check_of_assertion` gained the empty-schema arm its four siblings already carry, placed after type
resolution so `of_type_unresolved` is untouched. Blueprint §5.6 now says the structural half stays
late-bound at a codec seam rather than being compared against the empty schema.

### 3-2. Remove a stray file from the archive commit ([fba57ee](https://github.com/qmu/qfs/commit/fba57ee))

The archive call passed body text containing backticked snippets inside double quotes, so the shell
substituted them: an empty file named `of` was created and committed, and two phrases were dropped
from `a77f597`'s message. The file is deleted; the archived Final Report and this story carry the
full statements.

## 4. Outcome

Measured both directions: with the arm reverted the command exits 2 listing every asserted column
missing, with it restored it exits 0, and a described relation still exits 2 on a real mismatch.
2720 tests passed / 0 failed; clippy, fmt and the three anti-drift checks all exit 0.

## 5. Concerns

### The undescribable-relation rule is written five times, by hand

- **Severity:** moderate
- **Description:** `select`, `where`, `expand`, the transform input check and now `of` each carry their own `if …columns.is_empty()` guard with its own comment; nothing links them, which is why the fifth was missed for a month (see [a77f597](https://github.com/qmu/qfs/commit/a77f597) in `packages/qfs/crates/core/src/eval.rs`)
- **How to Fix:** Give the rule one name — a `Schema::is_undescribable()` predicate, or a single guard at the fold dispatcher — so the next fold's omission is a compile-time question rather than a review-time one.

### `of_assertion_failed` renders the Rust Debug struct, not prose

- **Severity:** low
- **Description:** The message is `OfAssertionFailed { ty: "(inline)", missing: [...], unexpected: [...] }` — the same leaked-internal-representation class this run minted `20260816175149` for on the post-decode path (see [a77f597](https://github.com/qmu/qfs/commit/a77f597) in `packages/qfs/crates/core/src/eval.rs`)
- **How to Fix:** Covered by `20260816175149`, whose acceptance criterion is that no operator-facing message contains Rust `Debug` struct syntax. Recorded here rather than re-ticketed.

## 6. Successful Development Patterns

- Reverting the one-line fix, rebuilding, and re-running the new test proved it fails without the change — the cheapest available guard against a regression test that would have passed anyway.
