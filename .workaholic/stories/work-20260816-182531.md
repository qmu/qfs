## 1. Overview

`unknown_column` and `not_expandable` are the same operator mistake on either side of a codec, but
after a `decode` they were re-wrapped as `codec_then_query` carrying the Rust `Debug` form of the
error enum. One mistake now has one code and one sentence wherever it lands.

**Highlights:**

1. A post-decode unknown or unexpandable column answers with the engine's own code and prose.
2. `codec_then_query` survives for what it always named, rendered through `Display`.
3. The remaining Debug-dump sites are a stated convention, reported unmet and ticketed, not quietly fixed.

## 2. Motivation

The FAQ promises an agent can branch on `code` — a promise this run's own PR #52 leant on when it
documented `unknown_column`. That row was true only before a `decode`. Worse, the message an
operator read was `UnknownColumn { stage: "where", name: "nope", available: [...] }` rather than the
sentence that names the available columns, which is the whole remedy. The information was never
missing: `EngineError` already carried both `code()` and `Display`, and a `{:?}` at the wrap site
was discarding them.

## 3. Changes

### 3-1. Give a post-decode refusal back its own code ([8674a81](https://github.com/qmu/qfs/commit/8674a81))

`run_trailing_ops`'s three wrap sites route through a new `post_decode_error`, which matches on the
two structured stage refusals and re-raises them with `EngineError::code()` and `Display`; every
other arm keeps `codec_then_query` and now renders prose too. The lowering and partitioning sites
swapped `{e:?}` for `{e}` — both error types already implement `Display`. The commit also carries
the follow-on ticket `20260816183441` (below).

## 4. Outcome

Measured with `EXIT` shown: `decode csv |> where nope == 1` and `decode csv |> expand a` now answer
`unknown_column` and `not_expandable` in prose, matching the pre-decode control in form; a `JOIN`
after a decode still answers `codec_then_query`, also in prose. 2721 tests passed / 0 failed;
clippy, fmt and the three anti-drift checks all exit 0. `docs/cookbook/faq.md` needed no edit — this
fix is what makes its new rows unconditionally true.

## 5. Concerns

### The ticket's no-Debug-syntax criterion is met at the codec seam only

- **Severity:** moderate
- **Description:** `EvalError` has no `Display` at all — `map_eval_error` documents `Debug` as the machine-facing message on purpose (owned, secret-free) — so `… |> of (nope text)` still answers `OfAssertionFailed { ty: "(inline)", missing: [...] }` and `… |> transform nosuch` still answers `TransformNotExecutable { name: "nosuch" }` (see [8674a81](https://github.com/qmu/qfs/commit/8674a81) in `packages/qfs/crates/exec/src/exec.rs`)
- **How to Fix:** Ticketed as `20260816183441` with the fork stated as an Open Decision: a 28-arm `Display` impl versus documenting `code` as the branch point. It is a ruling on an existing convention, which an unattended run does not hold.

### Two commit bodies in this run lost text to shell quoting at the archive seam

- **Severity:** low
- **Description:** `a77f597` (branch `work-20260816-181224`) lost two phrases to backtick command substitution and created a stray file; `8674a81` here has an empty body because the arguments were passed as `VAR=… bash …` prefix assignments, which the current shell expands before they exist (see [8674a81](https://github.com/qmu/qfs/commit/8674a81))
- **How to Fix:** The durable record is unaffected — each ticket's archived `## Final Report` and this story carry the full statements, and only the git trailer text was lost. Pass `archive.sh` body arguments from variables assigned on their own line, never through backticked text in double quotes or a command-prefix assignment.

## 6. Successful Development Patterns

- Reading the error types before writing the fix showed the fix was a formatting change, not a plumbing one: `EngineError`, `LowerError` and `PlanError` all already carried `code()` and `Display`, so the whole change was choosing which of them to trust.
