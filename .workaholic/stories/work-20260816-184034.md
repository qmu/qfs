## 1. Overview

The cookbook ratchet promised a skill can never teach a statement the binary rejects, and checked
only that each recipe parsed. It now also typechecks: every column a recipe names must exist on the
node it addresses, resolved through the binary's own cred-free describe registry.

**Highlights:**

1. 62 recipes typechecked against a floor of 20; the 19 unresolvable sources print by path.
2. Turning it on found two genuinely false recipes in `cross-service.md` — the exact class it was built for.
3. Demonstrated red on the ticket's own example before green.

## 2. Motivation

Parsing is the weakest possible reading of "verified true", and it let a whole article ship false:
eleven `github.md` recipes named thirteen columns `driver-github` does not carry, and the ratchet
was green the entire time. The articles are copied verbatim into installed Agent Skills, so a
fabricated column is not a documentation defect — it is an agent running a command that fails and
reporting the failure as the user's.

## 3. Changes

### 3-1. Typecheck the cookbook ratchet, not just parse it ([e17b0a5](https://github.com/qmu/qfs/commit/e17b0a5))

A second ratchet walks each recipe's checkable prefix and asserts its `where` / `select` /
`group by` / `order by` / `expand` / `aggregate` columns exist. It stops at the first stage after
which the schema is unknowable from describe alone, and its known-name set only ever grows, so it
can under-report but never invent a failure. Two false `/mail/inbox` recipes in `cross-service.md`
were corrected (`received_at` → `date`, `body` → `snippet`), the skill regenerated, and all four
plugin `version` fields moved `0.19.3 → 0.19.4`.

## 4. Outcome

The file moved from `crates/test/` to `xtask/tests/`: `qfs-test` is the wasm-clean harness that must
not link the binary, and `crates/qfs/tests/` trips the architecture guard that pins the binary off
`qfs-parser` — a dev-dependency counts, and the guard is right. xtask already links `qfs` for
`gen-docs` and ships in nothing. 2722 tests passed / 0 failed; clippy, fmt and the three anti-drift
checks all exit 0.

## 5. Concerns

### The ratchet is only ever as true as `describe`

- **Severity:** moderate
- **Description:** Three of the first five hits were false positives from passing `resolve_path`'s mount-stripped remainder to `Driver::describe`: `/github` errors loudly on that form, but the mail driver silently answers with the *message* schema for `/mail` (really `name`) and for an attachment node (really `filename, mime, size, content`) — defect 1 of the live concern `what-describe-says-is-not-what` (see [e17b0a5](https://github.com/qmu/qfs/commit/e17b0a5) in `packages/qfs/xtask/tests/cookbook_skills.rs`)
- **How to Fix:** Passing the full path (as `catalog.rs` does) fixed all three and raised the checked count 48 → 62. The residual risk stands: a describe regression turns this green test into a silent one, so the describe-seam work that concern asks for is what makes this ratchet trustworthy rather than merely present.

### Two of the ticket's scope lines were deliberately stretched

- **Severity:** low
- **Description:** The ticket lists "changing any article" as out of scope and names `crates/test/tests/cookbook_skills.rs` as the file; this branch changed `cross-service.md` and moved the file to `xtask/tests/` (see [e17b0a5](https://github.com/qmu/qfs/commit/e17b0a5))
- **How to Fix:** Both are argued in the archived Final Report. The article line meant "you need not re-fix `github.md`" — it cannot mean a recipe the new ratchet catches must stay false, or the ratchet could never land green. The move was forced by two guards that are both correct.

## 6. Successful Development Patterns

- Trying the obvious implementation first and measuring it — running each recipe through `Evaluator::eval` — disproved it in one run: an unknown `where` column evaluates Ok because `where` is late-bound for pushdown, so the evaluator cannot catch the very class the ticket was minted for.
