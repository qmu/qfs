## 1. Overview

The branch closed the last member of the "a stage that cannot be honored is refused, never ignored"
family: a `select` naming a column the relation does not carry is now a structured `unknown_column`
refusal at exit 2 instead of a projection that silently answered rows of nothing. Implementing it
uncovered that `select *` was itself broken — the identity projection was being pushed to drivers as
a column literally named `*`.

**Highlights:**

1. `|> select nosuchcol` refuses (`code: unknown_column`, `kind: usage`, exit 2) at plan time for a
   pushed projection and at runtime for a late-bound one, naming the available columns
2. `select *` and an empty projection are identity again — they were answering an empty schema
3. The shell's `ls` now emits its four-column listing only when the namespace describes it

## 2. Motivation

`where` and `expand` have refused an unknown column since 2026-07-25 and `/sql` always has, but a
projection dropped one: `|> select nosuchcol` returned the row **count** with an empty schema at
exit 0, so a consumer branching on `row_count` read "4 results" while every row was `{}`, and a
mixed projection silently lost its unknown half. The same statement therefore refused on `/sql` and
succeeded on the generic engine — an inconsistency the project would have had to write down as
intended had it kept the drop. The developer ruled **refuse** on 2026-07-26, leaving this branch the
implementation of a decision already made.

## 3. Changes

### 3-1. `select` on an unknown column is silently dropped ([a348369](https://github.com/qmu/qfs/commit/a348369))

Added the refusal on both roads a projection can travel: `PlanError::UnknownColumn` in the pushdown
planner (before a pushed projection reaches a driver that would narrow it away) and
`eval::project_checked` in the engine (over the batch a late-bound or post-decode read actually
delivered), both rendering the sentence `EngineError::UnknownColumn` already rendered. Identity
(`*`, empty) is now resolved before either branch, which is what exposed and fixed `select *`.

### 3-2. Mint the computed-projection sibling ticket ([080c009](https://github.com/qmu/qfs/commit/080c009))

Recorded `20260816191500`: the renamed/computed spelling (`select nosuch AS x`) lowers to
`ProjectExpr` and still answers one null per row, outside this ticket's name-only scope and its
ruling.

## 4. Outcome

Both measured commands from the ticket now refuse at exit 2 with the column and the available list,
and the post-decode form keeps the same `code` on the far side of a codec. 2736 workspace tests pass
(148 binaries); clippy, fmt, `gen-docs --check`, `gen-skills --check` and `check-migrations` are
clean. qfs 0.0.102 → 0.0.103; the qfs plugin 0.19.3 → 0.19.4 (the FAQ and cross-service articles
moved, so their skills regenerated).

## 5. Concerns

### The cookbook could only be swept where describe answers offline

- **Severity:** moderate
- **Description:** This refusal breaks any shipped recipe naming a column that does not exist, and
  the ratchet only parses. 35 plain projections were checked against `qfs describe` and passed
  (after one fix); 33 sit on paths needing a live connection (SQL tables, Slack, GitHub, git,
  declared drivers) and could not be checked here (see [a348369](https://github.com/qmu/qfs/commit/a348369) in `docs/cookbook/`)
- **How to Fix:** Land `20260725143000` (raise the cookbook ratchet from parse-only to a typecheck
  against the describe registry) — in flight on another branch — which closes the gap mechanically

### A computed projection still answers null for a column that does not exist

- **Severity:** moderate
- **Description:** `select nosuch AS x` lowers to `ProjectExpr` and passes neither new check, so two
  spellings of one question now answer two ways (see [080c009](https://github.com/qmu/qfs/commit/080c009) in `packages/qfs/crates/pushdown/src/lower.rs`)
- **How to Fix:** Ticketed as `20260816191500`; it carries the same refuse-vs-lenient decision the
  name-only form needed, and `eval_value` is shared with `EXTEND`/`SET`, so the check belongs at the
  projection site

### A described schema narrower than the delivered rows now refuses

- **Severity:** low
- **Description:** The plan-time check judges against what a driver *describes*; a driver that
  delivers columns it does not describe would refuse a `select` that used to work. The shell's `ls`
  was exactly that case and is fixed here (see [a348369](https://github.com/qmu/qfs/commit/a348369) in `packages/qfs/crates/exec/src/shell/desugar.rs`)
- **How to Fix:** Nothing to do unless one appears — the whole test suite is green, and the honest
  repair is to widen the driver's describe, which the describe-truthfulness concern already tracks

## 6. Successful Development Patterns

- Gate item 3 ("`*` and an empty projection stay identity, **pinned by a test**") found a live
  defect the ticket never suspected: writing the identity control as an acceptance criterion, not an

- Re-running the ticket's own measured commands against the built binary before touching code gave a
