## 1. Overview

`EvalError` was the one error type in the workspace with no `Display`, so every plan-time refusal
reached the operator as a Rust struct dump — from the layer that produces the refusals an operator
meets most often. It now renders sentences, at the same codes and the same exit codes.

**Highlights:**

1. All 24 `EvalError` arms Display; `map_eval_error`'s `{:?}` fallback is deleted.
2. `ResolveError` and `FnError`, the inner errors two arms delegate to, gained one each.
3. The ticket's Open Decision was ruled from the tree's own evidence, with the reasoning recorded.

## 2. Motivation

`|> of (nope text)` answered `OfAssertionFailed { ty: "(inline)", missing: ["nope"], … }` while the
engine next door answered `` `where` names column 'nope', which this relation does not carry ``. The
comment at the seam defended that on two real properties — the `Debug` form is owned and
secret-free — but the same function already carved the `HostScope` arm out of it, and PR #58 had
just shipped a project-wide criterion saying no operator-facing message carries `Debug` struct
syntax. Third sighting in three branches was the argument for ruling it rather than re-observing it.

## 3. Changes

### 3-1. `EvalError` has no `Display`, so a plan-time refusal reaches the operator as a Debug dump ([b206194](https://github.com/qmu/qfs/commit/b206194))

Hand-wrote `Display` over every `EvalError` arm — exhaustive, no `_` arm — plus the two inner
errors (`ResolveError`, `FnError`) that its delegating arms render through, and switched
`map_eval_error` to it. `code()` and the `ErrorKind` mapping are untouched, so nothing branching on
the envelope moves.

## 4. Outcome

The two measured commands answer prose at `of_assertion_failed`/exit 2 and
`transform_not_executable`/exit 5, and a new test constructs every arm to assert none carries Rust
`Debug` syntax. Gate green: 2723 tests, clippy, fmt, gen-docs, gen-skills, check-migrations.

## 5. Concerns

### The ticket's Open Decision was ruled by an unattended run

- **Severity:** moderate
- **Description:** the ticket called the `Display`-vs-document fork the developer's to settle; the
  run ruled it (a) from the convention, PR #58's criterion and the seam's own `HostScope` exception
  (see [b206194](https://github.com/qmu/qfs/commit/b206194) in `crates/core/src/eval.rs`).
- **How to Fix:** Confirm or reverse at review; reversal is one commit, since `code()` and the
  `ErrorKind` mapping are byte-identical either way.

### Nine `qfs` unit tests depend on an ambient `XDG_CONFIG_HOME`

- **Severity:** low
- **Description:** `cargo test --workspace` was red in a fresh container, nine tests panicking in
  `store.rs`'s `forbid_shared_home_fallback_in_tests`; all 2723 pass with the variable set.
- **How to Fix:** Wrap the nine in `testenv::HomeGuard` — ticketed as
  `20260816205752-nine-qfs-unit-tests-depend-on-an-ambient-xdg-config-home.md`.

## 6. Successful Development Patterns

- A convention with a hand-written exception for its most visible case is evidence against itself —
  reading `map_eval_error`'s `HostScope` carve-out that way is what turned a "developer must rule
  this" fork into a decidable one.
