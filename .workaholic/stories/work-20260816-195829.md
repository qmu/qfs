## 1. Overview

Installing a declared driver commits its statements to `/sys/drivers`; from then on **the installed
rows are the driver** and the shipped file is never read again. This branch gives an operator one
question that says whether their installation still matches the declaration the binary ships.

**Highlights:**

1. `/sys/declarations` — one row per installed declaration, `status` ∈ `current` / `stale` / `local`.
2. Identity is **derived** from the installed rows, never stamped: no new row kind, no column, no migration, no hashing crate.
3. Upgrade is **operator-initiated**; automatic re-install is rejected and the reason is recorded in blueprint §13.4.

## 2. Motivation

Two shipped declarations have already been corrected — the Chatwork `force=1` fix and the Slack
`CREATE LOOKUP` rewrite. Both reached the asset in the binary and neither reached anybody's
`/sys/drivers` rows, because nothing compares the two. Re-installing already works; the question was
missing. This branch's first pass settled two rulings and stopped at one fork — *which* existing
surface answers — with three candidates read and each blocked. That fork is settled here.

## 3. Changes

### 3-1. A declared driver has no upgrade path, so a shipped declaration fix never reaches a live mount ([b09b2da](https://github.com/qmu/qfs/commit/b09b2da))

`/sys/declarations` is a new SELECT-only relation on the closed `/sys` realm whose rows are derived
per read: the operator's `/sys/drivers` rows and the embedded asset — parsed through the production
splitter and grammar — reduce to the same one-entry-per-statement map, and the entries that
disagree are reported as the statements to re-install.

## 4. Outcome

`/sys/declarations |> where status == 'stale'` returns the statements to re-run, offline and
credential-free. `local` is a first-class third answer — a declaration you authored is not out of
date. Nothing upgrades itself: blueprint §13.4 (3) rules that out, because a read must not silently
write to your System DB.

## 5. Concerns

### A leftover row from a statement removed upstream is reported but cannot be removed

- **Severity:** moderate
- **Description:** When a shipped declaration drops a statement, its installed row is superseded by nothing and stays live. `/sys/declarations` now *reports* that key under `differs`, which is new, but there is still no supported way to delete it — `/sys/drivers` accepts `REMOVE` only by driver name (whole declaration), so clearing one leftover view means uninstalling and re-installing the driver. The ticket puts the removal ruling out of scope deliberately, and this makes it visible rather than fixing it.
- **How to Fix:** Rule the per-statement uninstall (a tombstone row versus a real delete is a genuine design choice) and give `/sys/drivers` the narrower `REMOVE`. Related to the open ticket `20260729163000-a-declared-view-cannot-be-removed`.

### The status is a snapshot of the running binary, not of the project

- **Severity:** low
- **Description:** The comparison is against the assets embedded in *this* binary, by design (the ticket puts a network fetch out of scope, and an offline answer is the point). So an operator on an old `qfs` sees `current` for a declaration a newer release has already corrected — the check answers "does my installation match my binary", never "is my binary current".
- **How to Fix:** Nothing here; upgrading the binary is the existing, separate path. Worth a sentence in the FAQ if operators read it as the stronger claim.

## 6. Successful Development Patterns

- **Compare per declaration item, not per script.** A whole-model blob says "something moved"; raw bytes call a comment edit a change. One entry per `CREATE …` makes the diff *the list of statements to re-run*, which is the answer the operator actually needed.
- **Build the shipped side through the production parser.** The comparison's other half is the embedded asset run through the same splitter and grammar the install path uses, so a test asserting every shipped declaration is `current` against itself fails loudly if either drifts — instead of telling every operator their up-to-date installation is stale.
- **`/sys/whoami` was the precedent that unlocked the design.** A `/sys` node whose rows are derived per read rather than stored already exists and is documented as such; finding it turned "no stamp, no migration" from a preference into an implementable one.
