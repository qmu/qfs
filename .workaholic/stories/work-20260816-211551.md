## 1. Overview

The Slack cookbook taught an upload, a download and a detach that no implementation had carried
since the compiled driver was retired — and the `qfs-slack` skill is generated from that article, so
every agent loading it was taught the same three. The detach is now real; the other two are gone,
each replaced by the reason it cannot exist.

**Highlights:**

1. `remove /slack/<ws>/files/<id>` is a declared `MAP REMOVE` firing `files.delete` behind the gate.
2. The upload and download are removed, with the constraint that forbids each stated in the article.
3. Plugin `0.19.4 → 0.20.0` — a taught-surface removal is a minor bump.

## 2. Motivation

Three operations survived their implementation because nothing checks a recipe against the declared
registry: the cookbook ratchet parses, and a write with no matching map previews green rather than
refusing. The article was the generation source for the skill, so the drift was propagating
outward — a documentation defect with an agent-facing blast radius.

## 3. Changes

### 3-1. The Slack cookbook teaches a file upload, download, and detach the driver does not implement ([5c456cc](https://github.com/qmu/qfs/commit/5c456cc))

Declared the detach (one request, so a map can express it), removed the upload (a three-call
external flow) and the download (needs `FOLLOW` to carry a bearer, which it never does), corrected
the `skill_description`, added the `files:write` scope row, and pointed `cross-service.md`'s Slack
tip at the gap instead of the deleted section.

## 4. Outcome

Every `/slack/…` path and verb the article teaches now exists in the declaration. The detach's wire
behaviour is pinned hermetically — exact URL and body — beside the `slack_twin_*` family. Gate
green: 2724 tests, clippy, fmt, gen-docs, gen-skills, check-migrations.

## 5. Concerns

### A Slack read cannot be verified in an unattended environment

- **Severity:** moderate
- **Description:** connecting a workspace is an OAuth account flow (`qfs connect … --driver slack`
  refuses without `qfs account add slack <label>`), so this run proved the detach's wire shape
  hermetically but exercised no live Slack read (see
  [5c456cc](https://github.com/qmu/qfs/commit/5c456cc)).
- **How to Fix:** run the article's listing recipes once against a real workspace, or record a
  `verification_handoff:` on future Slack tickets so the routing states it up front.

### An unmapped declared write previews as if it would work

- **Severity:** moderate
- **Description:** `upsert into /slack/<ws>/files` — no `MAP UPSERT` anywhere — still previews an
  ordinary effect row, which is how the false upload recipe passed every hand-check.
- **How to Fix:** refuse at plan time, naming the verbs the mount declares; ticketed as
  `20260816213014`.

## 6. Successful Development Patterns

- Splitting the direction per operation rather than ruling the ticket one way: each of the three had
  a different constraint, and "implement or delete" applied wholesale would have deleted a working
  detach or promised an inexpressible upload.
