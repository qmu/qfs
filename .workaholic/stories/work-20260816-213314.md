## 1. Overview

`20260816213014` was minted an hour earlier in the same run, from a preview that looked wrong. The
measurement says the preview *is* wrong, for a broader and simpler reason than the ticket guessed —
and the fix is one line whose consequences land somewhere the ticket never looked.

## 2. Motivation

PREVIEW is the instrument an operator reads before committing. Asked about a write to a path that
routes nowhere it answers with an ordinary effect row claiming one row affected, while the same
unrouted path **read** refuses `unknown_source`. A preview that cannot tell a write that will happen
from one with nowhere to go is not a safety instrument.

## 3. What the measurement says

Against `qfs 0.0.107`, with `chatwork.qfs` installed and connected by an `env:` secret:

```
$ qfs run "upsert into /chatwork/rooms/42/messages values ('hi')"      # ROUTED, verb not mapped
{"error":{"code":"unsupported_verb","kind":"capability","message":"node `/chatwork/rooms/42/messages` does not support `UPSERT`; supported: [SELECT, INSERT]"}}

$ qfs run "/nosuchdriver/x |> limit 1"                                  # UNROUTED read
{"error":{"code":"unknown_source","kind":"capability","message":"unknown source `nosuchdriver`"}}

$ qfs run "insert into /nosuchdriver/x values ('a')"                    # UNROUTED write
{"preview":{"rows":[{"id":0,"verb":"INSERT","target":{"driver":"nosuchdriver","path":"/nosuchdriver/x"},"affected":{"exact":1},…}],…},"committed":false}
```

So the capability gate is **already** doing the job the ticket asked for, wherever a mount exists —
including on a declared driver, whose per-segment verb set is derived from its own views and maps
(`DeclaredDriver::resources`). The ticket's Slack probe missed this only because `/slack/acme` was
never connected: with no mount there is no capability to check.

The literal-path fallback is deliberate and labelled — *"we still build a plan against the literal
path so the verb/irreversible semantics are testable without a mount (deferred path resolution,
ticket scope)"* — with the matching deferral in `resolve_effect`. `EvalError::UnroutedPath` already
exists and its own doc comment says it covers *"a `FROM` / **effect-target** path"*, so the arm was
written for this and never wired to it.

## 4. The fork

Removing the fallback costs exactly one workspace test — but that test fails on **DDL**, and that is
the fork. `CREATE TABLE` desugars to a catalog `INSERT INTO /sql/<conn>`, `CREATE TYPE` to one into
`/sys/drivers`; those paths are mounted in the CLI (a live `qfs apply` installs 17 rows happily) and
not in an evaluator built over a bare registry. So the choice is:

- **(a) Route the catalog everywhere** — the DDL desugars become ordinary routed writes and the
  refusal is uniform. Cleanest rule, widest change.
- **(b) Scope the refusal to non-catalog targets** — smallest diff, but it writes an exception into
  the very rule that is meant to have none.

Neither is derivable from the tree: (a) touches how every DDL statement is lowered, and the tree
contains no statement of where the `/sys` catalog is meant to be mounted.
