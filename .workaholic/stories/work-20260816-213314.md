## 1. Overview

A write whose target routes to no mounted driver now refuses at plan time instead of previewing as
an ordinary effect: PREVIEW answered `affected: {exact: 1}` at exit 0 for a path whose *read*
refused `unknown_source`.

**Highlights:**

1. `UPSERT INTO /slack/acme/files` with nothing connected: `unrouted_path`, exit 3 (was exit 0).
2. Removing the fallback exposed a second defect — no declared write on a `/slack/{ws}/…` mount
   could plan at all — so the shipped "post a message" map works again.
3. Fourteen tests wrote to `/mail/drafts` on a premise that stopped being true at CONNECT.

## 2. Motivation

PREVIEW is what an operator — or an agent — reads before committing, so it must never render a
plausible row for a write the system cannot perform. This is how `docs/cookbook/slack.md` could
teach an `UPSERT INTO /slack/<ws>/files` for months after the driver implementing it was deleted.

The ticket guessed the cause was a missing `CREATE MAP` check. The measurement its own step 1 asked
for said otherwise, and that correction is what made the fix one line: an effect target routing
**nowhere** built a plan against its literal path, while the read source beside it refused.

## 3. Changes

### 3-1. A write to a declared driver with no matching `CREATE MAP` previews as if it would work ([68632e3](https://github.com/qmu/qfs/commit/68632e3))

`Evaluator::eval_write` returns `EvalError::UnroutedPath` on a mount miss instead of falling back to
the literal path, and `RestApiConfig::resource_for_segment` resolves a `{param}`-token resource when
no literal segment matches — without which a parameterised declared mount answered no capabilities
at all and refused every write, mapped or not.

## 4. Outcome

The two halves of `eval` now agree on a mount miss. The ticket's own probe returns `unrouted_path`
at exit 3, and a new hermetic test over the *shipped* `slack_driver.qfs` pins all three shapes —
unrouted, routed-but-unmapped, and the mapped control. 2725 tests pass; every gate is green.

## 5. Concerns

### The routed refusal names a leading-segment aggregate, not the node's own verbs

- **Severity:** moderate
- **Description:** a declared mount's verb gate keys on the segment after the driver name, so the
  shipped slack declaration assembles to one resource carrying `[Select, Insert, Remove]` for every
  `/slack/<ws>/…` path — `REMOVE /slack/<ws>/users` passes a check that should refuse it, and the
  ticket's acceptance clause "naming the verbs `/slack/<ws>/files` does declare" is met only in the
  coarse sense (see [68632e3](https://github.com/qmu/qfs/commit/68632e3) in
  `packages/qfs/crates/qfs/src/declared_driver.rs`).
- **How to Fix:** resolve capabilities against the declared node path templates. Filed as
  `20260817001110`; the `{param}` wildcard shipped here is the restoration that made the layer
  answer at all, not an endorsement of its granularity.

### The routed half was verified hermetically, not against a live workspace

- **Severity:** low
- **Description:** the routed refusal and the mapped-write control are proved through
  `declared_describe_mount` over the shipped declaration bytes — the same constructor the CLI uses —
  but no live Slack workspace was connected in this environment, so the end-to-end CLI evidence
  covers the unrouted shape only.
- **How to Fix:** re-run the two routed statements against a connected workspace when one is at hand.

### The branch's deferred-concern judging was skipped

- **Severity:** low
- **Description:** `/report` Phase 1 judges the 26 open concerns against what landed since their
  origin commit; this run did not, so none were resolved or superseded by this branch.
- **How to Fix:** the next `/report` on a branch touching these areas picks them up; nothing is lost,
  the set merely re-surfaces.

## 6. Successful Development Patterns

- **Re-run the probe against the built binary before believing the source.** Reading `caps_for` said
  a routed mount already refuses an unmapped write; running it showed the refusal fires for *every*
  write with an empty verb list — two defensible mechanisms in series hiding each other.
- **When removing a fallback, read what its dependents were testing.** All fourteen exercised CLI or
  gate plumbing and picked `/mail/drafts` only because it needed no mount, so they were re-pointed
  at mounts a fresh host really has rather than granted an exception.
