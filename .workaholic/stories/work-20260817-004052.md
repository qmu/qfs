## 1. Overview

A declared driver's plan-time capability answer was derived per **leading path segment**, so every
node under a segment inherited the union of every verb declared anywhere beneath it. Against the
shipped Slack declaration — whose every node lives under `/slack/{ws}/…`, one segment for the whole
driver — that meant `remove /slack/<ws>/users` passed a gate no `CREATE MAP` declares. The gate now
answers per declared **node**, matched on the node's own path template.

**Highlights:**

1. `RestApiConfig` carries a per-node `NodeMap` table the capability gate reads first; the
   leading-segment `ResourceMap` aggregate is untouched, so every compiled `/rest` mount answers
   exactly as before.
2. A refusal now names the verbs *that node* declares — `remove /slack/<ws>/users` is refused
   naming `SELECT`, not the driver's whole union.
3. `write_irreversible` reads the same table, so a declared `IRREVERSIBLE` marking stays on the
   node that declared it instead of gating every sibling.

## 2. Motivation

Ticket `20260816213014` closed the other half of this — a write to a path routing to no mount at
all now refuses at plan time — and its acceptance also asked the routed refusal to name "the verbs
`/slack/<ws>/files` does declare". It named the leading segment's aggregate instead, which for a
one-resource declaration is every verb the driver declares anywhere. That ticket also had to add a
`{param}` wildcard to `resource_for_segment` to make a parameterised declared mount answer at all;
that wildcard restored the intended coarse semantics rather than endorsing them, and this branch is
what it was standing in for.

The gate was the last seam in the declared stack still keyed on a bare segment. `describe`, the
read facet and the apply facet all already match a node's **path template**
(`qfs_exec::declared::match_template`), which is why they agreed with each other and disagreed with
the gate — the classic shape where the defect lives in whichever seam speaks a different coordinate
space.

## 3. Changes

### 3-1. A declared mount's verb gate answers per node ([f43f691](https://github.com/qmu/qfs/commit/f43f691))

`RestApiConfig` gains an optional `nodes: Vec<NodeMap>` — each entry one declared node's
mount-relative path template plus the verbs that node itself declares — and `RestDriver::caps_for`
/ `write_irreversible` consult it whenever a mount declares one, falling back to the segment
answer for every compiled config. `DeclaredDriver::declared_nodes()` lifts the table from the same
view/map rows `resources()` already aggregates.

## 4. Outcome

A declared node advertises its own surface and nothing else: `remove /slack/<ws>/users` is refused
at plan time naming `SELECT`, while `remove /slack/<ws>/files/<id>` and `INSERT INTO
/slack/<ws>/<channel>/messages` still plan. The chatwork and cloudflare declarations keep answering
for every node they declare — pinned by a test that walks **every** node of all three shipped
declarations, built from the shipped `.qfs` bytes, and asserts the mount answers a verb *iff* a
declaration addressing that path says so.

## 6. Successful Development Patterns

- **Stub the fix back out and watch the tests fail.** With `.with_nodes(…)` replaced by an empty
  list, all three new qfs tests failed — cheap proof that they measure the change rather than
  restate it, and the only way to tell a ratchet from a tautology.
- **Re-derive the property from the shipped bytes, then quantify over every node.** Walking all
  three declarations' nodes and asserting "answers a verb iff a declaration addressing this path
  says so" catches the next declaration too, which a fixture asserting one path never would.
