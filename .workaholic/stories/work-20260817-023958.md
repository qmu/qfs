## 1. Overview

A declared (§13, query-based) driver could not be explored the way `SKILL.md` tells an agent to
explore everything else: `describe` returned a synthetic `value: Json` column where a read returned
the real ones, and a mount root advertised no children at all. The declaration itself now answers
`describe` — its `OF` types are the node's columns, its view templates the node's walkable
children — and the shipped Chatwork declaration carries the fields its endpoints deliver.

**Highlights:**

1. `describe` on a declared node reports the same column set a read of it delivers, pinned over two shipped declarations
2. A declared surface is walkable from its mount root down using `describe` output alone
3. The Chatwork declaration carries the room counts and the message sender, and the cookbook teaches them

## 2. Motivation

The documented agent loop opens `DESCRIBE → statement → PREVIEW → COMMIT` with "this is the **only**
thing you read", and against a declared driver that first step returned nothing usable. `/chatwork`
reported `child_address: none` with every verb false, so nothing pointed at `/chatwork/rooms`;
`/chatwork/rooms` reported one `value: Json` column while `run` on the same path returned the four
typed columns its `OF chatwork/room` promises. The only route from "the driver is mounted" to "here
is its surface" was reading the `.qfs` source.

Both answers were already in the declaration, so this was never missing information — only an
unasked question. That is what made it worth fixing rather than documenting: a declared driver
carries strictly more contract in config than a compiled one, and was strictly worse to work with.

## 3. Changes

### 3-1. A declared driver is undiscoverable through `describe` ([b7842f6](https://github.com/qmu/qfs/commit/b7842f6))

A new `DeclaredSurface` indexes each declared driver's view templates and resolves every `OF` type
against the declared-type registry; `DeclaredDescribeDriver` answers `describe` from that index and
delegates capabilities, procedures, pushdown, irreversibility and the applier to the inner stock
`RestDriver` untouched. `NodeDesc` gained driver-stated `children` and `row_contract`, which
`DescribeReport` composes into full child addresses under the node's own path.

## 4. Outcome

An agent can now enter the documented loop against a declared driver: walk `/chatwork` →
`/chatwork/rooms` → `/chatwork/rooms/{room}` → `…/messages` by child links, read the typed columns
at the leaf, and write a statement that runs. Chatwork stopped narrowing its rows — the room type
keeps its counts, the message type the sender lifted out of the nested `account` object — which is
what makes "which conversations have something new", attribution, and a threaded reply expressible
at all. The reply recipe and the incremental `send_time >` poll ship as cookbook recipes the data
now supports, the poll honest about being a local residual: the endpoint takes no since-parameter.

## 5. Concerns

### Branch-safety size gate blocked the automatic merge

- **Severity:** moderate
- **Description:** `scan-branch-safety.sh` returns `block` on `too-large-commit` — 1195 added implementation lines against a 500 threshold — so the unattended run demoted this unit to the PR path rather than merging it (see [b7842f6](https://github.com/qmu/qfs/commit/b7842f6)). The finding is `severity: override`, which only a present human can clear. The size is real but largely additive and split across three layers: the driver-contract fields, the new `declared_surface.rs`, and the tests plus cookbook prose that pin them.
- **How to Fix:** Review and merge by hand, or split a follow-up along the same seam (contract change / surface module / declaration + docs) if the size is judged a review problem rather than a scan artifact.

### Describe and run agree on column names, not on column types

- **Severity:** low
- **Description:** `shape_to_type` projects a read to the `OF` type's column *names* and takes each column's *type* from the delivered batch, so `describe` reports the declared `timestamp` for `send_time` where a read of a Chatwork epoch field reports `Int` (see [b7842f6](https://github.com/qmu/qfs/commit/b7842f6) in `packages/qfs/crates/exec/src/declared.rs`). The gate this branch answers is the column set, and that now matches exactly.
- **How to Fix:** Teach the shaper to coerce a delivered value to the declared `ColumnType` — a separate decision, since coercion changes what a read returns, not just what `describe` says about it.

### `provision::tests::offline_run_engine_does_not_mount_server` is flaky

- **Severity:** low
- **Description:** The test intermittently panics in `store::forbid_shared_home_fallback_in_tests` because `HomeGuard`'s env isolation is process-global and the suite runs in parallel. Observed once in three runs on code paths this branch does not touch; the full suite is green (2732 passed).
- **How to Fix:** Serialize the tests that depend on `HomeGuard`, or make the guard per-test rather than per-process. Worth a ticket if it recurs in CI.

## 6. Successful Development Patterns

- Lifting a shipped `.qfs` asset into the live model *through the real desugar* (`shipped_declared`: parse each statement, read the `/sys/drivers` row off the serialized `INSERT` effect) gives a test that cannot drift from what an install writes — unlike the older hand-rebuilt `shipped_slack_views()` fixtures.
- Pinning gate 1 by comparing two *production* paths against each other (the describe fold vs. `declared_eval::view_specs`' `of_columns`) rather than both against a shared constant, so the two answers cannot drift apart again without failing.
