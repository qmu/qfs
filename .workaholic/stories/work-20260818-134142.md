## 1. Overview

`qfs serve` now installs its SIGINT/SIGTERM handlers as its first act, so a signal arriving while
the daemon is still booting is latched and taken gracefully instead of killing the process
un-drained. The four serve e2e tests that guessed readiness with a fixed `sleep` now wait on the
daemon's own readiness line under a bounded, loud timeout.

**Highlights:**

1. A mid-boot signal exits 0 with the ledger drained — from 20 ms after spawn, where the boundary
   previously sat between 35 ms and 50 ms.
2. `systemctl stop` racing a slow boot waits the boot out instead of losing the ledger.
3. No serve e2e test guesses an interval; those scenarios also run ~4× faster.

## 2. Motivation

PR #74's merge commit reddened `main`: `serve_boots_mixed_fixture_and_drains_audit_on_sigint`
failed with `ExitStatus(unix_wait_status(2))` and passed on the next push over the same tree. Raw
wait status 2 is *terminated by signal 2*, not *exit code 2* — the process met SIGINT at its
default disposition. A probe over the real binary confirmed why: the listener was installed inside
`Runtime::run`, after boot, so everything before it was uncovered. That is a product defect, not a
test one — the `t36` contract stated in `run()`'s own doc comment ("a `systemctl stop` is a clean
drain, not an uncaught SIGTERM") did not hold while the daemon was booting, and the flake was that
gap seen from outside.

## 3. Changes

### 3-1. A shutdown signal arriving during boot takes the graceful path ([144e9b6](https://github.com/qmu/qfs/commit/144e9b6))

Adds `qfs_server::ShutdownSignal` — the SIGINT/SIGTERM listeners held as a value, so installing
them and awaiting them are separate moments — arms it at the top of `run_serve` before any boot
work, and has `Runtime::run` consume a latched mid-boot signal as its first act. `Runtime::run`
stays the single owner of the drain, and a failed boot still exits 1.

### 3-2. The serve e2e tests wait for observable readiness, never a fixed sleep ([1e84092](https://github.com/qmu/qfs/commit/1e84092))

Replaces the four `sleep`-then-signal guesses with a shared `ServeLog` helper that pumps the
child's stderr on its own thread and waits for a named readiness line under a bounded timeout,
failing loudly with the line awaited and the stderr actually seen. The consumed log stays
available, so no downstream assertion was weakened.

## 4. Outcome

The graceful-shutdown contract now holds for the whole of boot, and the unit file and `run()`'s doc
comment say so. The e2e suite proves it from outside at both signals, and can no longer redden a
merge by guessing how long boot takes on a loaded runner.

## 5. Concerns

### A ~12 ms pre-arm window remains before `main` reaches the serve entrypoint

- **Severity:** low
- **Description:** `main` reaches `run_serve` ~12 ms after `execve` — ~4.5 ms of loader and Rust
  init (irreducible: `qfs --version` costs that much) plus ~7 ms of `store::open_system_db()` and
  the clap parse — and a signal inside it still terminates the process un-drained (see
  [144e9b6](https://github.com/qmu/qfs/commit/144e9b6) in `packages/qfs/crates/qfs/src/main.rs`).
  The config-dependent part of boot is fully covered; this residual is a constant.
- **How to Fix:** Rule on whether the ~7 ms is worth an argv sniff in `main` plus a process-global
  stash for the pre-built runtime, or a changed `qfs_cmd::ServeLauncher` signature — both trade the
  composition-root discipline for a window that stays ≥4.5 ms regardless.

### A mid-boot stop now waits out the remaining boot

- **Severity:** low
- **Description:** The chosen resolution defers the exit to the first point the runtime is whole,
  so shutdown latency during boot equals the remaining boot time — ~27 ms for the 9-statement
  fixture, ~110 ms for a 200-statement one, against `TimeoutStopSec=30` (see
  [144e9b6](https://github.com/qmu/qfs/commit/144e9b6) in
  `packages/qfs/crates/server/src/runtime.rs`).
- **How to Fix:** Nothing today; revisit if a deployment's boot approaches `TimeoutStopSec`. The
  alternative — draining a half-built runtime — was rejected for making `entries=N` nondeterministic.

## 6. Successful Development Patterns

- Reproducing before designing paid: the hypothesis was right, but the first probe was silently
  wrong (a non-interactive shell sets SIGINT to `SIG_IGN` for `&` jobs, and it survives `execve`).
- Cutting each guessed `sleep` to 1 ms against the *already fixed* binary reproduced all four e2e
  sites, showing the pattern rather than one test was the defect.
- A bigger generated config, not a test hook in the product, made the mid-boot margin provable.

## 8. Notes

The residual pre-arm window is stated in the first ticket's Final Report with its measurements, and
`deploy/qfs.service` now documents the boot-inclusive contract next to `KillSignal=SIGTERM`.
