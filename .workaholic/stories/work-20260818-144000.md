## 1. Overview

`ci.yml` carried a `release-artifacts` job gated on `refs/tags/` inside a workflow whose `on: push:`
selects branches only, so it could never execute — and never had. The job is deleted, and
`packages/qfs/deploy/release.sh`, the script it was the sole caller of, is retired with it.

**Highlights:**

1. Unreachability confirmed against the Actions run list, not inferred from YAML alone.
2. `release.yml` and `install.sh` are byte-identical — the four native tarballs are untouched.
3. `docs/guide/repository.md`'s `deploy/` row no longer claims scripts CI calls.

## 2. Motivation

The cost of an unreachable job is not CI minutes — it burns none — but that `ci.yml` reads as though
it covers the release path when `release.yml` is what actually builds and publishes it. That exact
misreading produced the ticket this one was minted from: establishing what a tag push does and does
not run was the whole argument of `20260817164716`, which added `release.yml`'s own `docs-drift` job
for the same reason. This branch is the other half of that finding — the part that was outside the
provoking ticket's scope and so was deliberately not fixed opportunistically.

## 3. Changes

### 3-1. `ci.yml`'s `release-artifacts` job can never run ([9949519](https://github.com/qmu/qfs/commit/9949519))

Deleted the unreachable job and left a comment in its place recording why no release job belongs in
this workflow. Retired `packages/qfs/deploy/release.sh`, whose three outputs are each unconsumed —
musl `host-daemon` binaries that are not what ships, a `qfs.wasm` that is parked with no cdylib
entrypoint, and a copy of a golden wrangler fixture that stays in the tree. Corrected the `deploy/`
row in `docs/guide/repository.md` and bumped the patch to `0.0.113`.

## 4. Outcome

`ci.yml` now contains no job or step whose `if:` its own triggers cannot satisfy, and the repository
has exactly one release-artifact builder — `xtask dist`, driven from `release.yml` on a `v*` tag —
where it previously had two that could never meet.

## 5. Concerns

### The wasm and wrangler artifact recipe now lives only in git history

- **Severity:** low
- **Description:** `deploy/release.sh` was the only producer of the `wasm-release` `qfs.wasm` and the
  `wrangler.toml` template; retiring it leaves both with no producer (see [9949519](https://github.com/qmu/qfs/commit/9949519) in `packages/qfs/deploy/release.sh`)
- **How to Fix:** When ADR-0005's parked Workers host is unparked, add the wasm leg to `xtask dist`
  (which already accepts `--wasm`) rather than restoring the script.

## 6. Successful Development Patterns

- Confirming an unreachable CI job against the Actions run list before deleting it — `ci.yml` had
  zero runs on three sampled tags while `release.yml` had one on the newest — turned a YAML reading
  into a measured fact, which is what let the deletion also retire the script behind it.
