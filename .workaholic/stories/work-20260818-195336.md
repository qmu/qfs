## 1. Overview

The server guide's worked config, copied verbatim into a file and handed to `qfs serve`, did not boot. Three defects — missing statement terminators, a wrong endpoint shape in the bindings table, and a parse error pinned to the wrong line — are fixed at the generator source and locked in by a new ratchet.

**Highlights:**

1. Every config example now ends with `;` and the endpoint shape reads `on '<METHOD> /route' [policy <name>] as <stmt>`.
2. `qfs serve` reports a parse error against the failing statement's actual line, not always line 1.
3. A new ratchet parse-checks every `.qfs` fence in `docs/server.md`, so a documented config that cannot boot can no longer ship.

## 2. Motivation

`docs/server.md` is generated, and the tree's only guard on it — `gen-docs --check` — proves the rendered page matches the generator, never that the example the generator renders is *true*. So a config that every reader would paste and be told is wrong stayed green for as long as it existed. The same gap had already let a whole cookbook article ship false columns; the fix is the same shape it was there — a content-level ratchet that reads the page the way a reader does.

## 3. Changes

### 3-1. Fix the server guide's config example ([f5931f3](https://github.com/qmu/qfs/commit/f5931f3))

The generator (`crates/qfs/src/docs.rs`) now emits semicolon-terminated statements, the correct endpoint binding shape, and a sentence explaining that a config is a `;`-separated document; `apply_source` adds the newline count before a parse error's byte offset to the statement's first line; and `xtask/tests/server_guide_config.rs` splits and parse-checks every config fence, with a second test proving a `;`-less pair is one un-parseable statement so the ratchet cannot go vacuous.

## 4. Outcome

The guide's example config boots verbatim, the `;`-less two-liner now reports `line 2`, and the endpoint table matches what the parser accepts. `cargo fmt`, `clippy -D warnings`, `cargo test --workspace`, and `gen-docs --check` all pass, and the ratchet was confirmed to fail when a semicolon is deleted from the page.

## 5. Concerns

### The endpoint `do` form is caught by the table, not the ratchet

- **Severity:** low
- **Description:** `create endpoint x do /p` parses and fails at lower time (`CREATE ENDPOINT requires ON '<method> /route'`), so the fence-scoped parse ratchet cannot catch a regression to it — only the human-read table and `e2e_serve.rs` do (see [f5931f3](https://github.com/qmu/qfs/commit/f5931f3) in `packages/qfs/xtask/tests/server_guide_config.rs`)
- **How to Fix:** If lower-time shape errors in documented DDL become a recurring problem, extend the ratchet to boot each config rather than only parse it — accepting the `qfs-server` link that requires.

### The ratchet covers only the server guide

- **Severity:** low
- **Description:** `docs/language.md` and `docs/drivers.md` may carry examples with the same untested status; widening the ratchet was the ticket's open Consideration, left out of scope here (see [f5931f3](https://github.com/qmu/qfs/commit/f5931f3) in `packages/qfs/xtask/tests/server_guide_config.rs`)
- **How to Fix:** A follow-up ticket to generalize the fence extractor across the three generated pages, or fold it into the existing cookbook ratchet.
