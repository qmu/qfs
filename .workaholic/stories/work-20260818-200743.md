## 1. Overview

`CREATE VIEW` (and its `MAP`/`TYPE`/`DRIVER`/`SQL` siblings) had no inverse, so a mistaken or experimental declaration was permanent and lingered in `describe`'s advertised surface forever. This branch adds `REMOVE VIEW|MAP|SQL /<path>` and `REMOVE TYPE|DRIVER <name>`, refuses a driver removal that would orphan its views/maps or a live `CONNECT`, and turns the confusing `DROP` error into a pointer to the real verb.

**Highlights:**

1. A declared registration is removable by its `(kind, name)` key, disappears from the loader and `describe`, and the drop is audited.
2. Removing a driver with dependent views/maps, or one a `CONNECT` still targets, is refused with an error naming the dependents.
3. `DROP VIEW …` now returns "DROP is not a qfs verb; use REMOVE VIEW|MAP|SQL …" instead of a reserved-keyword complaint.

## 2. Motivation

Every `/sys/drivers` row was append-only and `assemble` resolved newest-per-key — which could supersede a redeclaration but never retract one. The discoverability work made this visibly worse: `describe /chatwork` now enumerates children, so undeletable scratch declarations appeared in the mount's advertised surface, teaching an agent paths the operator did not want offered. A surface is only trustworthy if the operator can curate what it offers.

## 3. Changes

### 3-1. Let a declared registration be removed ([861e1f0](https://github.com/qmu/qfs/commit/861e1f0))

Five `REMOVE <noun>` grammar forms desugar to `REMOVE /sys/drivers WHERE name == '<name>' AND kind == '<kind>'`; `/sys/drivers` gains the `Remove` capability; the applier reads name+kind off the selector, enforces the dependency refusal against live registry and `CONNECT` state, and drops exactly the `(kind, name)` row via a new audited `remove_declaration`. The one-shot addressing guard learns the new nouns, `DROP` gets a pointed error, and a commit-time leg failure now renders through `Display` (not `Debug`), so a refusal reads as prose. Includes parser, applier, real-DB install/drop/audit, and addressing tests.

## 4. Outcome

`REMOVE VIEW|MAP|SQL|TYPE|DRIVER` parse, preview, and commit; the dropped node leaves the registry, the loader, and `describe`; a view and a map sharing a node path drop independently; both dependency refusals fire and name what still depends on the target; and `DROP` names the missing capability. `cargo test --workspace` (149 binaries, 0 failed), `clippy -D warnings`, `fmt --check`, `gen-docs --check`, and `gen-skills --check` all pass.

- **Severity:** low
- **Description:** the ticket proposed `DROP VIEW`; this ships `REMOVE VIEW` to honor the codebase's stated "REMOVE is the one frozen destructive verb / no DROP keyword" rule (see [861e1f0](https://github.com/qmu/qfs/commit/861e1f0) in `packages/qfs/crates/parser/src/grammar.rs`). `DROP` still gets a pointed error pointing at `REMOVE`
- **How to Fix:** none needed — recorded as the resolved design decision; revisit only if a `DROP` alias is later wanted
