## 1. Overview

Two pull requests closed one defect from opposite ends within a day, and `main` ended up carrying
two per-node capability tables built from the same declarations. They are now one:
`DeclaredNodeDesc`, read by both the describe and the live mount.

**Highlights:**

1. `NodeMap` and its whole `RestApiConfig` surface are deleted; `caps_for` keeps one caller shape.
2. The live mount gets the declared table, so which mount you ask no longer decides the answer.
3. The collapse forced a rule choice — first-match or union — and the union won, on the applier's own behaviour.

## 2. Motivation

PR #46 made `capabilities` per node while making `describe` per node, building `DeclaredNodeDesc`
on `RestDriver.nodes`. PR #64 made `capabilities` and `write_irreversible` per node from the config
side, building `NodeMap` on `RestApiConfig.nodes`. Both landed, and only the describe mount was
given the first table — so there `caps_for`'s declared branch was dead code while
`write_irreversible` still read the config, and the live mount read the config for both.

Nothing was a live wrong answer — both derive from the same rows — but it reinstated the shape
`20260728085253` closed "by construction rather than by keeping two sources agreeing", with the
extra hazard that the two tables carried different fields, so neither could be deleted without
moving something first.

## 3. Changes

### 3-1. Collapse the declared mount to one node table ([11af4f9](https://github.com/qmu/qfs/commit/11af4f9))

`DeclaredNodeDesc` gained `irreversible_verbs`, populated from each map's `IRREVERSIBLE` flag;
`write_irreversible` reads it whenever the mount declares nodes; `live_rest_driver` now takes the
declared type registry and calls `.with_declared_nodes(...)`, fed the real registry both call sites
already had in hand. `NodeMap`, `RestApiConfig::nodes`, `with_nodes`, `declares_nodes`,
`verbs_for_path`, `irreversible_for_path` and `DeclaredDriver::declared_nodes()` are gone.

## 4. Outcome

`grep -r NodeMap packages/qfs/crates` returns nothing, and new hermetic tests walk every declared
node of the shipped slack, chatwork and cloudflare declarations through both mounts, for all five
verbs, on capabilities and irreversibility. `cargo test --workspace`, clippy `-D warnings`,
`fmt --check`, `gen-docs --check` and `gen-skills --check` all exit 0. Version `0.0.123`.

## 5. Concerns

### The describe mount's capability answer widened on one path shape

- **Severity:** low
- **Description:** The two tables resolved a path differently — `capabilities()` took the first matching node, the config unioned every match — so collapsing them had to pick one rule. The union won (see [11af4f9](https://github.com/qmu/qfs/commit/11af4f9) in `packages/qfs/crates/driver-http/src/lib.rs`), which widens what the describe mount advertises wherever two distinct templates address one concrete path, e.g. `{tenant}/things` alongside `acme/things`. No shipped declaration has that shape today.
- **How to Fix:** Nothing to fix unless a declaration adopts overlapping templates and the wider answer proves wrong; the union is what the apply seam already does (it performs a verb when any matching node declares it), and the narrower rule would have dropped an irreversible marking carried by a later-matching template.

## 6. Successful Development Patterns

- Negative-control a regression test before trusting it: reverting only the live mount's `with_declared_nodes` call turned the cross-mount walk red with a named node and verb, which is what proves the test measures the split rather than passing for unrelated reasons.
- When merging two derivations of one fact, read the lookup as carefully as the contents — these agreed on their data and disagreed on their resolution rule, so a mechanical deletion of either would have changed behaviour with no test to say so.
