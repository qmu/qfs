- **Description:** `CLOUDFLARE_API_TOKEN` is still the token minted with `Zone → Workers Routes → Edit` on `qmu.co.jp`, so a leak from GitHub Actions can bind a Worker to any hostname in the zone, the apex included. ### Publishing can only be verified indirectly from an unattended container

- **Severity:** low
- **Description:** Outbound HTTPS to both docs hostnames is refused by the proxy, so `curl .../version.json` — the check the deployment record names first — cannot run here. Every unattended verification of this mission's promise therefore reads the workflow run rather than the served site, which proves the deploy step succeeded and not that the hostname serves it.
- **How to Fix:** A person, or any session with egress to those hostnames, reads `version.json` once and confirms it matches the merge commit.
