## 1. Overview

Four unattended runs have claimed the Cloudflare docs-deploy token ticket and re-blocked it, each
opening a pull request restating the same three console acts. This branch measures why that cannot
change on its own and writes the finding onto the ticket, ending the loop.

**Highlights:**

1. The Actions secrets API is refused through this session's proxy for **reads**, not only writes.
2. Narrowing the token changes nothing in CI or `version.json`, so no tick can detect it.
3. The two dispositions that close the loop are named on the ticket; both are the developer's.

## 2. Motivation

The three prior blocked entries each read as "still outstanding, check again next time", assuming a
later run could find the work done. It cannot. `GET repos/qmu/qfs/actions/secrets` returns only
names and timestamps, never a value, and is refused 403 anyway — so a runner cannot see when
`CLOUDFLARE_API_TOKEN` was last written. Nor indirectly: with no `routes` declared, a narrow token
and the wide one both deploy green and stamp an identical `version.json`, and scope itself reads
only from the dashboard or an authenticated `/user/tokens/verify`, which needs a credential.

### A ticket no runner can verify is re-offered to every tick

- **Severity:** moderate
- **Description:** Parking the claim behind an open pull request stops the loop only while that pull request stays open; merging or closing it without acting returns the ticket to the queue for the next unattended run to claim and re-block (see [478db1f](https://github.com/qmu/qfs/commit/478db1f) in `.workaholic/tickets/todo/20260818124500-the-docs-deploy-token-cannot-be-narrowed-while-routes-are-declared.md`)
- **How to Fix:** Set `verification_handoff:` on the ticket so the unit takes the declared-handoff route on sight, or archive the ticket by hand once the three console acts are done.

## 6. Successful Development Patterns

- Proving a blocker *unobservable* is worth more than proving it *outstanding*: the first ends the retry loop, the second invites it. The read-side 403 was the check that turned one into the other, and it cost one API call.
