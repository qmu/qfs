## 1. Overview

Slack connections now use their bound account for both reads and posts. An agent chooses `/slack-a/…` or `/slack-b/…` to operate as the corresponding profile after setup with `qfs connect … --account …`.

**Highlights:**

1. Select Slack authentication through the connection path.
2. Refuse missing or revoked accounts without falling back to default.
3. Preserve explicit secret references and existing stored driver declarations.

## 2. Motivation

Connections already stored their account labels, but Slack's declared `AUTH BEARER` driver ignored those labels and read the default credential. This could authenticate a read or post as the wrong profile despite using the documented connection commands.

## 3. Changes

### 3-1. Resolve the mounted account ([386b342](https://github.com/qmu/qfs/commit/386b342))

The shared credential resolver maps bearer authentication to the account stored on the selected mount, keeping explicit `--secret` references authoritative. Cookbook examples and the generated agent skill demonstrate two user profiles; binary and plugin versions advance to 0.0.129 and 0.22.1. Four mechanical notation updates in existing hash/redaction code also restore compatibility with Rust 1.98 Clippy.
