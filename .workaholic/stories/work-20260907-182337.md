## 1. Overview

QFS reported committed:true when a Slack reply returned HTTP 200 with ok:false and missing_post_type. Slack failures now stop the operation and produce a nonzero exit with a bounded service error code. JSON requests carry Content-Type: application/json.

## 2. Motivation

A real thread reply was never delivered even though the CLI reported success. HTTP status alone did not establish Slack acceptance, and read errors obscured the service's error code. Existing mounted-account authentication worked; the missing boundary was application response validation.

## 3. Changes

- Add an opt-in JSON success contract to the HTTP driver, enabled for the exact Slack Web API base URL, including existing persisted declarations.
- Reject failed or malformed envelopes before counting effects or continuing pagination; preserve safe error codes through reads and CLI commits without automatic POST retries.
- Share JSON body/header generation for writes and read-over-POST. Generic REST responses retain existing semantics.
- Add transport, mounted-account, and CLI regressions; update Slack documentation and bump QFS to 0.0.130 and plugins to 0.22.2.

Implementation: [c9a956d](https://github.com/qmu/qfs/commit/c9a956d).

## 4. Outcome

All 2,800 workspace tests passed (2 ignored), plus 529 serialized QFS tests (1 ignored). Format, clippy, generated documentation and skills checks plus migration integrity passed. GitHub CI passed native tests, cross-compilation, wasm, docs, and viewer checks.

The release candidate read internal_with_yosan using the existing yodex credentials. A nonexistent channel returned channel_not_found and exit 5. Failed-post behavior is verified through the real CLI execution entry with a hermetic HTTP transport; no additional live messages were sent.

## Notes

Contract selection covers https://slack.com/api with an optional trailing slash. Custom proxy endpoints require explicit response-contract composition. Unknown service error strings are sanitized instead of echoed. Existing unrelated deferred concerns are unchanged.
