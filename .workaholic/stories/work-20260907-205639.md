## 1. Overview

QFS gained a tested Codex installation path and one structural guard for the skill tree shared with Claude Code. Its preview guidance now matches the runtime boundary: schema description is available offline, but write evaluation requires a routed mount.

**Highlights:**

1. Verify both plugin hosts, exact skill registration, versions, symlinks, and generated content in CI.
2. Document and smoke-test Codex marketplace installation of `qfs@qfs` 0.22.3.
3. Pin unrouted cloud writes to exit 3 without emitting a misleading preview.

## 2. Motivation

Static JSON consistency did not prove that Codex could install and expose the shared QFS skills, while existing documentation promised successful previews for cloud paths with no installed route. The branch closed both evidence gaps without duplicating skills or weakening the evaluator's intentional refusal of impossible writes.

## 3. Changes

### 3-1. Verify Codex plugin distribution and prevent shared-skill drift ([b1f1052](https://github.com/qmu/qfs/commit/b1f1052))

The shared package now has a locally runnable checker and 11 negative fixtures covering both host manifests and marketplaces, exact registrations, synchronized versions, symlinks, and generated Cookbook bodies. Installation instructions were verified with Codex CLI 0.153.4, and CI runs the same distribution gate.

### 3-2. Align preview guidance with the requirement for a routed mount ([b1f1052](https://github.com/qmu/qfs/commit/b1f1052))

Human and agent guidance now separates compiled offline description from route-dependent write evaluation, using `/sys/policies` for a real zero-setup preview. A CLI integration test preserves the exit-3 `unrouted_path` refusal and empty preview output for an unmounted cloud write.

## 4. Outcome

QFS advances to 0.0.131 and the shared plugin to 0.22.3. Local distribution tests, documentation build, isolated runtime checks, and the Codex install smoke passed; [GitHub CI](https://github.com/qmu/qfs/actions/runs/34226679905) passed all eight native, lint, format, generation, docs, viewer, wasm, and cross-compilation jobs.

## 5. Successful Development Patterns

- Test generated equality and host loading separately: together they prove one source tree is both synchronized and actually discoverable.
- Use a built-in routed path for zero-setup preview examples so side-effect freedom is not confused with route availability.
