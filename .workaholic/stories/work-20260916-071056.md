## 1. Overview

Slack writes now reject missing JSON message content locally and return actionable service errors.
The operation and corrective guidance use a closed vocabulary that never copies private response values.

**Highlights:**

1. Reject missing, null, and empty text-only posts before credentials or HTTP.
2. Preserve safe Slack error codes and explain unknown or malformed upstream errors.
3. Document explicit text bindings and retain valid rich-content alternatives.

## 2. Motivation

The [reported reply failure](https://github.com/qmu/qfs/issues/108) disappeared when the text column
was explicit. Recording fixtures confirmed positional VALUES produced `text: null` for both
messages and an installed reply map. This extends 51bcbbb's application-response validation
without weakening its response secrecy; the original live upstream code remains unobserved.

## 3. Changes

### Slack write diagnostics

[Implementation fd6928d](https://github.com/qmu/qfs/commit/fd6928d) adds a composed JSON content
contract, recognizes no_text and other safe codes, and attaches bounded operation/correction text.
The cookbook and generated Slack skill describe the result. Versions: qfs 0.0.132, plugin 0.22.4.
