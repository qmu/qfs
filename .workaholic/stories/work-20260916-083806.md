## 1. Overview

Slack posting examples now bind message text explicitly, and CALL accepts hyphenated mount qualifiers such as `slack-a.react`. Recording HTTP fixtures verify the intended payload and account.

## 2. Motivation

A positional message could populate the first schema column while the post map read absent text. Advertised CALL names on hyphenated mounts failed to parse before reaching the existing procedure remapping.

The previous mounted-account work established authentication by connection path. This repair keeps that boundary and makes its advertised procedure spelling executable.

## 3. Changes

### 3-1. Bind Slack message examples explicitly ([582a57c](https://github.com/qmu/qfs/commit/582a57c))

The embedded skill, executable example, Slack cookbook and automation examples use `VALUES (text)`. Seven actual shipped posting examples commit their expected channel/text payload; a separate fixture verifies explicit thread fields under reordered schemas.

### 3-2. Enable advertised calls on named mounts ([0dafb4a](https://github.com/qmu/qfs/commit/0dafb4a))

A CALL-specific qualifier parser accepts contiguous hyphenated names without changing expression parsing. All five advertised Slack procedures preserve lookup ordering, exact payloads, irreversible flags and each of two mounted accounts' credentials.
