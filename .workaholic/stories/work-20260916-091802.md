## 1. Overview

Added authenticated Slack attachment reads through the selected mount. The scoped transport resolves a file ID with Slack and downloads intact bytes with the same account.

**Highlights:**

1. Discover `content: bytes` at `/<slack-mount>/<workspace>/files/<file>/content`.
2. Reject untrusted download destinations and every redirect while preserving credential-free FOLLOW.
3. List an attached PDF and copy its bytes through one named mount using the documented recipe.

## 2. Motivation

Slack file listings exposed metadata while private attachment downloads were unavailable. The scoped file transport reuses the selected-account credential adapter introduced in 277504f, enabling PDF retrieval without widening generic FOLLOW's credential boundary or adding query grammar.

## 3. Changes

### 3-1. Read Slack attachment bytes through the authenticated selected mount ([04e3fda](https://github.com/qmu/qfs/commit/04e3fdac47314a96dbd1cfedc29b2a2d7902d50f))

Added the typed content view and a provider-specific transport primitive that calls `files.info`, validates its HTTPS `files.slack.com/files-pri/` destination, and reads bytes using the same account.
